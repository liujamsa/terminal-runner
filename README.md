# 脚本终端

一个原生 Android 脚本启动器。支持从 MT 管理器导入 `.sh`、普通或 Root 模式执行、实时合并输出、stdin 输入和停止进程。

## 功能

- 全局亮色主题，并提供固定的“脚本 / 通道 / 进程”底部 Tab 导航。
- 每次启动创建独立控制台、运行快照、输入输出通道和通知，互不复用；最多同时运行 4 个通道。
- 每个已保存脚本拥有固定的私有工作目录和 `HOME`，脚本写入的卡密、配置与缓存会保留到下次运行。
- “关闭当前通道”只断开该控制台的显示、输入和通知，不再向脚本发送 Ctrl+C、TERM、KILL，也不会结束脚本进程组；需要结束残留脚本时在进程页明确操作。
- 底部“通道”页集中显示所有启动中和运行中的控制台，可直接返回对应控制台或快速结束单个通道；汇总通知也会直接打开此页面。
- 脚本列表支持自定义显示名称，不修改原文件名或来源文件。
- 脚本设置支持重新选择并更新脚本源；只替换内容，保留显示名称、排序位置、固定工作区和记忆开关。
- 脚本列表可长按左侧把手拖动排序并持久保存；卡片本身不会启动脚本，只有右侧播放按钮会运行。
- 输入记忆默认关闭；手动开启后会同时学习“提示语 + 输入值”，下次看到对应提示后才逐项发送，普通与 Root 模式均可使用。
- 自动输入期间可以随时手动接管；一旦手动发送，本次剩余自动输入立即停止。直接回车的空输入也可以记录和回放。
- 记录只对内容 SHA-256 完全相同的脚本生效；脚本内容变化后会进入重新学习状态，避免把旧参数发给新版脚本。
- Root 进程监控按 CPU 排序，显示应用图标、名称、包名、PID 和 RSS；无应用图标时使用默认图标。
- 进程页默认显示全部进程，并可在 CPU 与内存占用降序之间切换。
- 进程页只允许结束严格匹配本应用 `files/runs/` 快照且启动时间一致的脚本主进程；第三方 APP 与所有系统、持久化、厂商核心、内核、Root 服务、未知包和本应用均只读。

## 构建

本机环境可直接执行：

```powershell
gradle assembleDebug --offline
```

Debug APK 输出到 `app/build/outputs/apk/debug/app-debug.apk`。项目也包含 Gradle Wrapper；首次使用 Wrapper 时需要能下载 Gradle 8.7，或在 Android Studio 中选择本机的 Gradle 8.7。

## 运行方式

- 普通模式调用 `/system/bin/sh <脚本>`，权限等同于应用自身。
- Root 模式先执行 `su -c id` 检查授权；授权成功后保存开关状态，脚本会直接按当前模式启动。
- 从 MT 管理器选择的单个脚本会导入应用私有目录，确保临时文件授权失效后仍可运行。
- 文本脚本的标准输入通过进程管道发送，适用于 `read` 等交互。
- Root 脚本拥有完整 Root 权限，脚本自身执行 `reboot`、结束系统进程或耗尽资源等操作无法由启动器隔离。
- 运行前检查文件魔数：文本脚本使用 `/system/bin/sh`；即使文件名以 `.sh` 结尾，ELF 可执行文件也会在真正的 PTY 中启动，并支持 Root 交互式终端环境。

## 第三方组件

ARM64 PTY 支持使用固定版本的 FuryTerminal `libterm.so`。来源、版本和 SHA-256 记录在 APK 的 `assets/THIRD_PARTY_NOTICES.txt` 中。

`samples/interactive-demo.sh` 是无系统副作用的测试脚本。它只在该脚本的私有 `HOME` 中保存一行名称，并在三段输入之间各等待 2 秒，用于验证持久化、按提示自动输入和空回车。

## 文件入口

- 右上角 `+` 优先打开已安装的 MT 管理器（支持 `bin.mt.plus.canary` 和 `bin.mt.plus`），未安装或无法处理时回退到系统文件选择器。
